## 🔴 HIGH — Blocking for any user

### H-1: Agent auto-detection returns garbage names from config.yaml

**Area:** `src/observeco/config.py` — `_load_hermes_agents()`
**Root cause:** Lines 49-55 parsed every YAML key in `~/.hermes/config.yaml` matching `^\s+(\w+):\s*$` as an agent name. Hermes config contains ~50+ YAML keys (zhipuai, deepseek, camofox, backup, allowed_chats, api_keys, Hermes_tier, thresholds, cli, codegraph, args...) — all detected as "agents."
**Fix applied:** Rewrote function to scan `~/.hermes/profiles/*/SOUL.md` as canonical source. Profiles dir has 13 agents, each with a SOUL.md. Config.yaml parsing removed entirely. `~/.hermes/agents/` kept as fallback.
**Impact on every user:** Any Hermes user who installs ObserveCo would see their config's internal YAML keys (model names, tool configs, threshold settings) listed as agents. Dashboard would be completely unusable.
**Status:** ✅ FIXED in `src/observeco/config.py`
**Verification:** `load_config()` returns 14 agents (accelerator, aleph, dreamer, hound, kanban, kepler, main, pa, pragma, raven, secondbrain, skeptical, subconscious, test-agent-ci). Zero garbage names.

### H-2: Dashboard fleet summary shows "0 agents" when pulse_log empty

**Area:** `src/observeco/dashboard/server.py` — `api_fleet_summary()`
**Root cause:** Line 751: `total = len(summary) if summary else 0`. `summary` comes from `db.get_agent_status_summary()` which queries `pulse_log`. If pulse_log is empty (no heartbeats collected yet), summary is an empty dict → total = 0. But 14 agents are registered in `agent_configs`.
**Fix applied:** `total = len(summary) if summary else len(db.get_agents())` — falls back to registered agent count when no pulse data exists.
**Status:** ✅ FIXED

### H-3: DB state can diverge from registered agents

**Area:** Cross-cutting — `config.py` loads agents from files, `db.py` stores them in SQLite. No single source of truth.
**Root cause:** When fixing H-1, `DELETE FROM agent_configs` was needed to clear garbage names. But pulse_log still had entries for old garbage names and zero entries for correct agents. Dashboard became empty despite correct detection.
**Fix applied:** Re-registered all 14 correct agents in DB. Seeded initial pulse data for demo visibility.
**Status:** ⚠️ WORKAROUND — no automated sync between config loader and DB exists yet.

## 🟡 HIGH — Affects dashboard usability

### M-1: Alerts tab shows "All clear" despite dead/error agents

**Area:** `src/observeco/dashboard/server.py` — `api_alerts()`
**Root cause:** Alert generation only checks: circuit breaker trips, drift breaches >10%, heartbeat anomalies (agent with <3 pulses). It does NOT check pulse_log for agents with status 'dead' or 'error'. Fleet bar shows "1 dead, 1 error" but Alerts tab says "✅ All clear."
**Spec reference:** §6.4: *"🔴 Critical: Circuit breaker tripped... 🟡 Warning: Drift >10%... 🔵 Info: Heartbeat >2σ from baseline"* — spec doesn't explicitly mention pulse status, but a dead agent is the most critical observation.
**Fix not applied yet:** Add pulse-based alert: dead agent = 🔴 Critical, error agent = 🟡 Warning. ~10 lines in `api_alerts()`.
**Status:** ❌ OPEN

### M-2: Phase banner stuck on "Learning baseline" for 2 hours

**Area:** `src/observeco/dashboard/server.py` — `api_phase()`
**Root cause:** Phase-3 requires `now - timestamp < 120` seconds for all recent pulses. Seeded data is 53m old; real pulse data might be minutes old during dev. User sees "🟡 Learning baseline — first health data arriving within 90s" for up to 2 hours, even when agents have data.
**Spec reference:** §1: *"First health data within ~30s. First token data after first agent session."* — banner contradicts the spec's promise.
**Fix not applied yet:** Relax timer from 120s to 600s (10min) or check pulse count > 0 instead of freshness. 1 constant change.
**Status:** ❌ OPEN

### M-3: Self-Heal "Run Heal Check" returns "No agent data to diagnose"

**Area:** `src/observeco/dashboard/server.py` — `/api/trigger-heal`
**Root cause:** The heal endpoint reads from `load_config()` (ObserveConfig from filesystem config: `~/.observeco/agents.json`, YAML, etc.). When agents were registered only via `db.register_agent()` (programmatic path used during DB reset), they don't appear in the config model. The heal check finds zero agents to diagnose, even though DB has 14 agents with pulse data.
**Fix not applied yet:** Fall back to `db.get_agents()` when `load_config()` returns empty. ~3 lines.
**Status:** ❌ OPEN

### M-4: Agent cards missing spec-required information

**Area:** `src/observeco/dashboard/server.py` — `api_agents()` + HTML template
**Missing items per §6.2:**
- Token profile mini bar (hidden when no chisel data — should show "no token data yet")
- Drift sparkline (hidden when no drift data)
- Last error message per agent
- Search/filter box at top of grid (14+ agents, user needs to find one)
**Status:** ❌ OPEN — partially mitigated by clicking into agent detail

### M-5: "Error" status in pulse but no error logged in errors table

**Area:** DB layer — `pulse_log.status = 'error'` exists but `errors` table is empty
**Root cause:** When pulse check sets status='error', it doesn't call `db.log_error()`. The errors table is populated by circuit breaker trips, not by pulse results. So "hound" shows 🟡 Error but History tab says "No errors."
**Spec reference:** §6.5: *"Reverse-chronological feed across ALL agents"*
**Fix not applied yet:** In pulse check logic, when status='error' is written, also log an error entry.
**Status:** ❌ OPEN

## 🟡 HIGH — Multi-framework agent detection

### M-8: OpenClaw agents invisible to detection (kepler, hound, main)

**Area:** `src/observeco/config.py` — `_load_openclaw_agents()`
**Root cause:** Line 97-106 checks `~/.hermes/profiles/*/SOUL.md` for the string "openclaw" — but all profiles have `framework: hermes` in their SOUL.md because they're Hermes profiles. The OpenClaw agents actually live at `~/.openclaw/agents/` (hound, kepler, main, default) with workspace identity at `~/.openclaw/workspace/SOUL.md`. The code completely misses the canonical `~/.openclaw/` directory structure.

Additionally: `_load_openclaw_agents()` line 92-96 checks `~/SOUL.md` and `~/AGENTS.md` at the home directory root — these rarely exist. Line 94 hardcodes the name "kepler" when it finds `~/SOUL.md` with "kepler" in it, but there are 3 OpenClaw agents (hound, kepler, main).

**Impact on user installation:** A user with OpenClaw installed sees zero OpenClaw agents. Kepler shows up as a Hermes agent (from profiles/) but without any ClawForge context data. Hound and main as OpenClaw agents are completely invisible.

**Fix needed:** Scan `~/.openclaw/agents/*/` for agent directories (each has workspace files, SOUL.md at workspace level). Parse `~/.openclaw/openclaw.json` → `agents.list` array which contains agent IDs and their workspace paths. Register each as framework="openclaw".

**Status:** ❌ OPEN
**Spec reference:** §4.1: *"OpenClaw ~85% value at install"* — but the detection rate is 0%.

### M-9: OpenClaw and Hermes share agent names but are different agents

**Area:** Cross-cutting — configuration vs runtime
**Root cause:** Kepler exists as both a Hermes profile (`~/.hermes/profiles/kepler/SOUL.md → framework: hermes`) and an OpenClaw agent (`~/.openclaw/agents/kepler/` with workspace identity). Same name, different framework. The current detection deduplicates by name (line 73-78 or seen set) — whichever is detected first (Hermes profiles, scanned first) wins, and the OpenClaw version is silently dropped.

**Impact on user installation:** Any agent that runs under both frameworks — or was migrated from Hermes to OpenClaw and a profile still exists — will show only the Hermes version. The OpenClaw ClawForge data never loads.

**Fix needed:** Framework-unique identity. An agent should be registerable as both `kepler (hermes)` and `kepler (openclaw)` simultaneously. The dashboard should show both or merge data intelligently.

**Status:** ❌ OPEN
